## 1. API 설계 개요

### 1.1 설계 목적

> RESTful 원칙에 따라 클라이언트-서버 간 통신 규격을 정의하여 일관되고 확장 가능한 API를 제공

### 1.2 설계 원칙

* **RESTful 아키텍처**: HTTP 메서드와 상태 코드의 올바른 사용
* **일관성**: 모든 API 엔드포인트에서 동일한 규칙 적용
* **버전 관리**: URL 경로를 통한 버전 구분
* **보안**: JWT 기반 인증 또는 외부 기능을 이용한 인증
* **성능**: 페이지네이션, 캐싱
* **문서화**: 명확한 요청/응답 스펙 제공

### 1.3 기술 스택

* **프레임워크**: Spring Boot 4.0.8
* **데이터베이스**: MariaDB, Spring Data JPA, Flyway
* **인증**: JWT (JSON Web Token)
* **직렬화**: JSON
* **API 문서**: OpenAPI 3.0 (Swagger)

## 2. API 공통 규칙

### 2.1 URL 설계 규칙

| 규칙 | 설명 | 좋은 예 | 나쁜 예 |
| --- | --- | --- | --- |
| **명사 사용** | 동사가 아닌 명사로 리소스 표현 | `/api/analysis` | `/api/getAnalysis` |
| **복수형 사용** | 컬렉션은 복수형으로 표현 | `/api/members` | `/api/member` |
| **계층 구조** | 리소스 간 관계를 URL로 표현 | `/api/members/1/analysis` | `/api/getMemberAnalysis` |
| **소문자 사용** | URL은 소문자와 하이픈 사용 | `/api/book-categories` | `/api/BookCategories` |
| **동작 표현** | HTTP 메서드로 동작 구분 | `POST /api/analysis` | `/api/createAnalysis` |

### 2.2 HTTP 메서드 사용 규칙

| 메서드 | 용도 | 멱등성 | 안전성 | 예시 |
| --- | --- | --- | --- | --- |
| **GET** | 리소스 조회 | ✅ | ✅ | `GET /api/analysis/1` |
| **POST** | 리소스 생성 | ❌ | ❌ | `POST /api/analysis` |
| **PUT** | 리소스 전체 수정 | ✅ | ❌ | `PUT /api/books/123` |
| **PATCH** | 리소스 부분 수정 | ❌ | ❌ | `PATCH /api/books/123` |
| **DELETE** | 리소스 삭제 | ✅ | ❌ | `DELETE /api/books/123` |

### 2.3 HTTP 상태 코드 가이드

| 코드 | 상태 | 설명 | 사용 예시 |
| --- | --- | --- | --- |
| **200** | OK | 성공 (데이터 포함) | GET 요청 성공 |
| **201** | Created | 리소스 생성 성공 | POST 요청 성공 |
| **204** | No Content | 성공 (응답 데이터 없음) | DELETE 요청 성공 |
| **400** | Bad Request | 잘못된 요청 | 입력값 검증 실패 (@Valid) |
| **401** | Unauthorized | 인증 필요 | 토큰 없음/만료 |
| **403** | Forbidden | 권한 없음 | 접근 거부 |
| **404** | Not Found | 리소스 없음 | 존재하지 않는 분석 ID |
| **409** | Conflict | 충돌 | 중복 생성 시도 |
| **500** | Internal Server Error | 서버 오류 | LLM API 연동 실패 등 서버 에러 |

### 2.4 공통 요청 헤더

```http
Content-Type: application/json
Accept: application/json
Authorization: Bearer {JWT_TOKEN}

```

### 2.5 공통 응답 형식

#### 성공 응답 (단일 객체)

```json
{
  "success": true,
  "data": {
    // 실제 데이터
  },
  "message": "요청이 성공적으로 처리되었습니다",
  "timestamp": "2026-09-22T10:30:00Z"
}

```

#### 에러 응답 (ErrorObject 규격)

```json
{
  "statusCode": 400,
  "message": "입력항목 검증 오류",
  "timestamp": "2026-09-22 10:30:00",
  "errors": {
    "code": "분석할 코드는 필수입니다.",
    "language": "언어 타입은 필수입니다."
  }
}

```

## 3. API 상세 스펙 (Code Security Analysis)

### 3.1 코드 분석 실행

클라이언트가 전송한 소스 코드를 기반으로 LLM을 활용해 취약점을 검사하고 결과를 저장합니다.

* **URL**: `/analysis`
* **Method**: `POST`
* **Description**: 입력된 코드의 보안 취약점을 분석하고 결과를 반환합니다.

#### Request Body

| 필드명 | 타입 | 필수여부 | 제약조건 | 설명 |
| --- | --- | --- | --- | --- |
| `language` | String | Y | 최대 50자 | 프로그래밍 언어 (예: JAVA, PYTHON) |
| `code` | String | Y | NotBlank | 분석 대상 소스 코드 원본 |

```json
{
  "language": "JAVA",
  "code": "public class Test { public void getUser(String userId) { String sql = \"SELECT * FROM users WHERE id = \" + userId; } }"
}

```

#### Response (200 OK)

```json
{
  "success": true,
  "message": "요청이 성공적으로 처리되었습니다",
  "timestamp": "2026-09-22T10:38:00Z",
  "data": {
    "analysisId": 1,
    "language": "JAVA",
    "totalCount": 1,
    "highCount": 1,
    "vulnerabilities": [
      {
        "id": 1,
        "type": "SQL Injection",
        "severity": "HIGH",
        "lineNumber": 1,
        "problemCode": "String sql = \"SELECT * FROM users WHERE id = \" + userId;",
        "description": "사용자 입력값이 SQL 문장과 직접 연결되어 DB 유출 위험이 있습니다.",
        "aiExplanation": "PreparedStatement를 사용하여 바인딩 처리하세요.",
        "afterCode": "String sql = \"SELECT * FROM users WHERE id = ?\";"
      }
    ]
  }
}

```

---

### 3.2 단건 분석 결과 조회

이전에 수행된 특정 코드 분석 결과를 상세 조회합니다.

* **URL**: `/analysis/{id}`
* **Method**: `GET`
* **Description**: 분석 ID(`id`)를 통해 기존의 분석 결과 및 취약점 목록을 조회합니다.

#### Request Parameter (Path Variable)

| 파라미터명 | 타입 | 필수여부 | 설명 |
| --- | --- | --- | --- |
| `id` | Long | Y | 분석 내역의 고유 식별자(PK) |

#### Response (200 OK)

*(`3.1 코드 분석 실행`의 성공 응답 형태와 동일)*

#### Response (404 Not Found)

요청한 ID에 해당하는 분석 결과가 DB에 존재하지 않을 경우 반환됩니다.

```json
{
  "statusCode": 404,
  "message": "해당 자원을 찾을 수 없습니다.",
  "timestamp": "2026-09-22 10:39:15"
}

```
